# Проверка безопасности Calmap

Дата: 14.10.2026. Объект: backend (FastAPI), Telegram-бот оплаты, мобильное
приложение (Flutter), инфраструктура (Docker Compose, Caddy, CI).

## Метод

- Ручной разбор кода всех компонентов: аутентификация, авторизация объектов,
  платежи, ввод данных, хранение секретов, логи.
- Замеры: время работы планировщика меню на худшем входе.
- Проверка зависимостей: `pip-audit` по зафиксированным версиям (backend, бот);
  уязвимостей нет.
- Поиск секретов в истории git: секретов нет; в истории есть старый IP сервера
  (информационно).
- Проверка Caddy: подмена `X-Forwarded-For` от клиента не проходит; конфигурация
  проверена `caddy validate`.
- Регрессионные тесты на каждую исправленную уязвимость: `backend/tests/test_security.py`,
  `bot/tests`, `mobile/test/local_first_test.dart`.

## Найдено и исправлено

Уровни: **H** — высокий, **M** — средний, **L** — низкий.

### Backend

| # | Уровень | Проблема | Исправление |
|---|---|---|---|
| B1 | H | Один запрос `meal_slots` из 10–11 слотов занимал воркер на 30–60 с и дольше (перебор всех сочетаний в синхронном коде) | Паросочетание Куна вместо перебора; не больше 6 слотов; решатель в пуле потоков |
| B2 | H | Параллельные запросы распознавания фото / AI-консультанта одного пользователя ждали блокировку и держали соединения пула → отказ всего API | Занятая блокировка сразу отвечает 429; пул 10+10, ожидание соединения не дольше 10 с |
| B3 | M | Один IP мог исчерпать суточный бюджет SMS, перебирая номера | Лимит кодов в сутки на IPv4 / IPv6 /64 (`SMS_PER_NETWORK_DAILY`), предупреждение при 80% бюджета |
| B4 | M | Обход лимитов на номер: Unicode-цифры давали «другой» номер; параллельные запросы проходили проверки одновременно; посторонний мог исчерпать часовой лимит владельца | Только ASCII-цифры; блокировка на номер; лимиты на пару «номер + сеть» и общий на номер |
| B5 | M | Без строки `ENV` в `.env` включались test-токены входа (в пространстве реальных VK ID), `/docs`, CORS `*`, stub-SMS | По умолчанию `production` и `DEBUG=false`; test-токены только при `ENV=local`, в отдельном пространстве `vktest:`; секрет `change-me…` отклоняется |
| B6 | M | Сессии нельзя было отозвать: refresh-токен действовал 60 дней после выдачи нового, выхода не было | Таблица сессий; refresh-токен меняется при каждом обновлении, повтор старого завершает сессию; `POST /v1/auth/logout`; приложение завершает сессию на сервере при выходе |
| B7 | L | Неограниченные списки во входных данных и даты тренировок любого года | Ограничения длины списков; даты тренировок ±400 дней |
| B8 | L | Поиск продуктов полным перебором таблицы; `%` и `_` работали как шаблоны | GIN-индекс `pg_trgm` по `lower(name)`; экранирование |
| B9 | L | Не-ASCII в `X-Bot-Secret` давал 500 | Сравнение байтов |
| B10 | L | Названия продуктов из открытых каталогов попадали в системную инструкцию AI как текст | Данные в отдельном размеченном блоке, названия укорочены до 60 символов |
| B12 | M | Удаление аккаунта выполнялось по одному токену: украденная сессия могла безвозвратно удалить данные | Код из SMS на номер аккаунта (`POST /v1/auth/me/deletion-code`, отдельное назначение кода, не подходит для входа); аккаунт без номера — вход не старше 10 минут; отказ — 403, не 401 |
| B11 | Инфо | `/health` раскрывал окружение; лог SMS.ru содержал номера; ошибка магазинов раскрывала имена настроек; один ключ для JWT и HMAC кодов; `avatar_url` принимал `javascript:` | Убрано окружение; в лог только коды ответа; общий текст ошибки; производный ключ для кодов; `avatar_url` только `https://` |

Проверено без замечаний: JWT (HS256 зафиксирован, тип и срок проверяются), коды
SMS (`secrets`, HMAC, 5 попыток, `FOR UPDATE`), отсутствие перечисления
аккаунтов, принадлежность объектов во всех эндпоинтах, параметризованный SQL,
защита путей статики и юридических страниц, отсутствие SSRF, скрытые ошибки и
`/docs` в production, непривилегированный контейнер.

## Остаточные риски

| Риск | Почему не устранён | Мера |
|---|---|---|
| Номер телефона переходит новому абоненту → новый владелец входит в старый аккаунт | Свойство входа по SMS | Решение владельца продукта: подтверждение для аккаунтов без входа более 6 месяцев |
| SMS-бомбинг одного номера с нескольких сетей (до 10 кодов в час) и распределённая накрутка бюджета | Без капчи / аттестации устройства полностью не решается | Подключить проверку устройства (Play Integrity / App Attest) или капчу после N запросов; следить за предупреждением 80% |
| Один IPv4 у многих абонентов мобильного оператора (CGNAT) | Лимит на сеть может задеть добросовестных пользователей | `SMS_PER_NETWORK_DAILY=100`; поднять при жалобах |
| Вход VK ID полагается на проверку VK, что токен выдан нашему приложению | Требует проверки на стороне VK | Проверить на тестовом стенде до включения VK ID |
| Два одновременных первых входа одним VK-аккаунтом → 500 | Редкая гонка, данные не страдают | Исправить при следующей доработке входа |
| GitHub Actions подключены по тегам, образы Docker — по тегам | Нужны SHA-дайджесты, которых нет в репозитории | Закрепить по SHA (например, через Dependabot) |
| `RECIPE_IMAGE_STORAGE_DIR` из одного имени каталога откроет `/app` через `/media` | Зависит от настройки | Оставлять значение по умолчанию `media/recipes` |

## Действия оператора перед запуском

1. Заполнить `.env` и `.env.bot` по образцам; `chmod 600 .env .env.bot`.
2. Задать разные пароли `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `BOT_DB_PASSWORD`;
   для существующей базы выполнить `docker compose exec db sh /db-roles.sh`
   (RELEASE.md, раздел «Переход со старой схемы»).
3. Задать `BACKUP_PASSPHRASE` и хранить его вне сервера; копировать бэкапы на
   другой сервер.
4. Сверить `YOOKASSA_ALLOWED_IPS` со списком на странице ЮKassa
   «Входящие уведомления».
5. Следить в логах backend-а за сообщениями `daily SMS limit` и `80% of the daily
   SMS limit`.
6. При утечке `TELEGRAM_BOT_API_SECRET` — сменить его в `.env` и `.env.bot`; при утечке
   `SECRET_KEY` — сменить: все сессии и неиспользованные коды станут недействительны.

## Обновление зависимостей

```bash
cd backend   # или bot
python3.11 -m venv /tmp/lock && /tmp/lock/bin/pip install .
/tmp/lock/bin/pip freeze --exclude calmap-backend > requirements.lock   # calmap-bot для бота
/tmp/lock/bin/pip install pip-audit && /tmp/lock/bin/pip-audit -r requirements.lock
```
