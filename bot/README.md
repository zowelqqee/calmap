# Calmap — бот оплаты подписки

Telegram-бот продаёт подписку BASE и PRO через ЮKassa и сообщает backend-у Calmap
статус оплаты. Приложение на бота не ссылается; пользователь приходит в бот сам.

## Сценарий

1. `/start` → приветствие и кнопка «📱 Поделиться номером» (`request_contact`).
   Принимается только собственный контакт отправителя (`contact.user_id == from.id`),
   отправленный кнопкой: пересланные сообщения отклоняются. Бот работает только в
   личном чате.
2. Бот вызывает `POST /v1/bot/link`: аккаунт находится по номеру входа в
   приложение. Номер и id аккаунта Calmap хранятся в боте: номер — для чека 54-ФЗ,
   id — чтобы оплата и возврат относились именно к этому аккаунту.
3. Под полем ввода появляется меню: **📅 Моя подписка · 💳 Продлить · ❓ Помощь**.
4. **Карточка подписки**: тариф, дата окончания, сколько дней осталось и шкала
   ▰▰▰▱▱. Кнопки: «🔄 Продлить <тариф> · цена» (одно нажатие), «⭐ Перейти на PRO»
   для BASE, все тарифы, напоминания вкл/выкл, помощь. После окончания срока
   карточка напоминает, что данные сохранены.
5. **Подтверждение**: цена, что входит, точная дата окончания после оплаты (с
   пересчётом остатка при смене тарифа), «без автопродления», ссылка на соглашение,
   кнопка «💳 Оплатить».
6. **Счёт**: кнопка «Перейти к оплате» (ЮKassa, карта или СБП) и «🔄 Я оплатил —
   проверить» — бот сразу опрашивает ЮKassa, не дожидаясь уведомления.
7. После оплаты — «🎉 Оплата прошла!» с новой датой; приложение открывает доступ.

«💳 Продлить» в меню ведёт сразу к подтверждению текущего тарифа: от меню до
страницы оплаты — два нажатия. Навигация внутри карточки редактирует одно
сообщение, чат не засоряется. Любой непонятный текст открывает карточку.

## Правила срока

| Ситуация | Новый срок |
|---|---|
| Подписки нет, пробный период или срок истёк | сейчас + 30 дней |
| Тот же тариф ещё действует | текущий конец + 30 дней |
| Другой тариф ещё действует | остаток пересчитывается по цене (20 дней BASE → 20 × 299/499 ≈ 12 дней PRO) + 30 дней |
| Оплачено больше чем на год вперёд | новая покупка не предлагается |

Описание бота в Telegram (экран до «Старт») и короткое описание задаются при запуске
из `texts.BOT_DESCRIPTION` и `texts.BOT_SHORT_DESCRIPTION`.

## Надёжность

- Платёж создаётся с ключом идемпотентности, равным id записи в боте. Неоплаченный
  счёт на тот же тариф переиспользуется в течение часа; не больше 5 счетов в час.
- Платёж привязан к аккаунту Calmap, для которого он создан: если Telegram-аккаунт
  за это время привязали к другому аккаунту, backend отклоняет событие (409),
  деньги другому аккаунту не засчитываются, пользователь получает сообщение
  обратиться в поддержку.
- Тело уведомления ЮKassa не используется: только id, состояние берётся из API.
  Неизвестный id игнорируется.
- Сверка раз в минуту: незавершённые платежи за последние 24 часа опрашиваются в
  ЮKassa (на случай потерянного уведомления), неотправленные в backend —
  отправляются снова с тем же сроком (паузы 2, 4, 8 … минут, до 6 часов). Событие
  в backend идемпотентно по `yookassa:<payment_id>`.
- Доставки одного пользователя выполняются последовательно (advisory lock), поэтому
  две быстрые покупки продлевают срок одна за другой.
- Возврат (`refund.succeeded`) отправляет `status: revoked`, когда возвращённая
  сумма (`refunded_amount` платежа) достигла суммы платежа; меньший возврат ничего
  не меняет. Возврат оформляется в
  личном кабинете ЮKassa.
- Если аккаунт Calmap удалён после оплаты, пользователь один раз получает сообщение
  обратиться в поддержку, платёж остаётся в базе бота с пометкой.

## Напоминания

Раз в час бот запрашивает `GET /v1/bot/subscriptions/expiring?within_hours=72&ended_within_hours=48`
и присылает: за 3 дня, за день и в день окончания пробного периода или подписки —
каждое один раз за период. В каждом напоминании — кнопка продления текущего тарифа
(или выбора тарифа после пробного периода) и «🔕 Не напоминать». Отправляются только
пользователям, привязанным в боте и не отключившим напоминания.

## Команды

| Команда | Действие |
|---|---|
| `/start` | привязать аккаунт по номеру |
| `/status`, «📅 Моя подписка» | карточка подписки |
| `/pay`, «💳 Продлить» | продление текущего тарифа или выбор тарифа |
| `/help`, «❓ Помощь» | частые вопросы и поддержка |
| `/reminders_off`, `/reminders_on` | отключить или включить напоминания об окончании срока |
| `/forget` | удалить номер телефона из бота и привязку Telegram в backend-е (записи о платежах остаются без номера) |

## Данные

Таблицы в схеме `bot` той же PostgreSQL, что у backend-а (миграции backend-а их не
трогают): `bot.users` (Telegram ID, телефон), `bot.payments` (платежи ЮKassa, без
телефона), `bot.reminders`. Схема создаётся при старте.

## Настройка

Переменные читаются из `backend/.env.bot` (образец — `backend/.env.bot.example`);
секреты backend-а боту не передаются:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_BOT_API_SECRET` | общий секрет с backend-ом |
| `DATABASE_URL` | роль `calmap_bot`, доступ только к схеме `bot` |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | магазин ЮKassa |
| `YOOKASSA_RETURN_URL` | `https://t.me/<имя_бота>` — куда вернуть после оплаты |
| `YOOKASSA_RECEIPTS`, `YOOKASSA_VAT_CODE` | чеки 54-ФЗ и код НДС (1 — без НДС) |
| `PRICE_BASE_RUB`, `PRICE_PRO_RUB`, `SUBSCRIPTION_DAYS` | цены и срок (по умолчанию 299, 499, 30) |
| `LEGAL_CONTACT_EMAIL` | контакт поддержки в `/help` |
| `PUBLIC_BASE_URL` | `https://`-домен для ссылок на соглашение и политику (обязателен) |

В личном кабинете ЮKassa → «HTTP-уведомления»: URL
`https://<домен>/yookassa/webhook`, события `payment.succeeded`,
`payment.canceled`, `refund.succeeded`. Caddy принимает `/yookassa/*` только с
адресов ЮKassa (`YOOKASSA_ALLOWED_IPS`), бот дополнительно проверяет формат id.

Запуск — вместе с backend-ом: `docker compose --profile https up -d --build`.
