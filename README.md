# Calmap

Мобильное приложение (iOS/Android, Flutter) и backend (FastAPI + PostgreSQL) для
планирования питания под бюджет, рынок РФ.

Функции: вход по номеру телефона (SMS-код), онбординг-анкета, расчёт норм КБЖУ, рацион на неделю в пределах бюджета,
замена блюд, список покупок, дневник питания (поиск, ручной ввод, распознавание по
фото), тренировки с картой мышц, прогресс веса и замеров, AI-консультант (PRO),
подписка BASE/PRO с оплатой в Telegram-боте и пробным периодом 3 дня, удаление
аккаунта, правовые документы.

## Локальный запуск

Backend (нужны Python 3.11+ и PostgreSQL 16):

```bash
cd backend
python3.11 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env
createdb calmap
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed.run
.venv/bin/uvicorn app.main:app --reload
```

Документация API: http://localhost:8000/docs (в production отключена).

Клиент:

```bash
cd mobile
cp config/development.example.json config/development.json
flutter pub get
flutter run --dart-define-from-file=config/development.json
```

## Проверки

```bash
cd backend && .venv/bin/ruff check app tests && .venv/bin/python -m pytest -q   # 150 тестов
cd mobile && flutter analyze && flutter test                                    # 23 теста + 4 golden (только macOS)
cd bot && .venv/bin/ruff check calmap_bot tests && .venv/bin/python -m pytest -q # 36 тестов
```

Тесты backend создают отдельную БД `calmap_test` и прогоняют те же миграции Alembic,
что и production. Те же проверки и сборка Docker-образа выполняются в GitHub Actions
(`.github/workflows/ci.yml`) на каждый pull request.

## Ключевые решения

**Оптимизатор рациона — два уровня оптимизации, не нейросеть.** Уровень 1
(`menu.py`) выбирает блюда: seeded greedy + локальный поиск. Уровень 2
(`portions.py`) подбирает граммовку: выпуклая квадратичная задача, проекционный
градиентный спуск с точной проекцией на бюджетное полупространство.

**Солвер не отвечает «решения нет».** При недостижимых ограничениях он возвращает
ближайший план и список `relaxations` — что пришлось ослабить и на сколько.

**Аллергены исключаются с запасом.** «Арахис» исключает и орехи, «Морепродукты» —
ракообразных и моллюсков. Неизвестный аллерген отклоняется (422), а не игнорируется.

**LLM не считает числа.** Распознавание возвращает продукт и граммы, КБЖУ считается
по базе. Экран подтверждения обязателен.

**Цены версионированы**, стоимость плана фиксируется в момент генерации; нутриенты
копируются в запись дневника.

**Доступ определяется только статусом оплаты в БД.** Таблица `subscriptions`
(одна строка на пользователя) хранит `payment_status` (`none` / `paid` / `expired` /
`revoked`), `paid_until`, тариф и `trial_ends_at`. Записывает статус только
Telegram-бот оплаты через `/v1/bot/*` (общий секрет). Приложение статус только
читает (`GET /v1/me/subscription`):

| Состояние | Когда | Доступ |
|---|---|---|
| `trial` | первые 3 дня после регистрации, оплат не было | да, лимиты BASE |
| `active` | `payment_status = paid` и `paid_until` в будущем | да, лимиты тарифа |
| `trial_ended` | пробный период прошёл, оплат не было | нет |
| `expired` | оплаченный период закончился | нет |
| `revoked` | бот сообщил об отмене или возврате | нет |

Без доступа сервер отвечает 402 `subscription_required` на все функции, кроме
входа, анкеты, профиля, статуса подписки и удаления аккаунта. Приложение показывает
экран «Подписка закончилась. Продлите её, чтобы продолжить» (или «Пробный период
закончился»); ссылок и кнопок оплаты в приложении нет. За 3 дня до окончания на
главном экране появляется предупреждение. Повторного пробного периода после оплаты нет.

| Тариф | Фото в день | Дней плана | AI-консультант |
|---|---|---|---|
| Пробный (3 дня) | 5 | 7 | — |
| BASE | 5 | 7 | — |
| PRO | 30 | 28 | 200 сообщений в месяц |

Цены задаются в боте (`PRICE_BASE_RUB=299`, `PRICE_PRO_RUB=499` за 30 дней). Лимиты — в `backend/app/db/models/subscription.py`.
Повторная отправка того же фото не списывает лимит.

**Даты по Москве.** «Сегодня», дневные лимиты и даты планов считаются в
`APP_TIMEZONE` (по умолчанию `Europe/Moscow`) — и в процессе, и в сессиях PostgreSQL.

## Известные ограничения

- **Каталог курируемый** (69 продуктов, 73 рецепта, средние цены Москвы). Перед
  масштабированием нужны проверка нутриентов диетологом и региональные цены.
  Импорт Open Food Facts описан в [RELEASE.md](RELEASE.md).
- **Город в профиле** пока только отображается; цены считаются по Москве, это
  указано пользователю.
- **Вход через VK ID** (дополнительный) не проверен на устройстве: VK ID при обмене
  кода требует `device_id`, который AppAuth не передаёт. Кнопка скрыта, пока в
  сборке не задан `VK_CLIENT_ID`. Основной вход — по SMS.
- **Ограничение частоты входа** хранится в памяти процесса: на одном сервере с
  несколькими worker-ами лимит умножается на их число.
- Скриншоты в `mobile/screenshots/` сделаны до последних изменений экрана профиля.
